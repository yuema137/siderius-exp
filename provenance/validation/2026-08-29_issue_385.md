# SIDERIUS Issue #385 External Reproduction

## Scope

This witness defines an out-of-tree task whose scientific deliverable contains
both each model prediction and the supervision value associated with the same
validation sample. The values come from a temporary physical data root. It
performs CPU inference with an identity model and uses no private dataset.

## Pre-repair result

SIDERIUS revision: `98610b8ded2277598749cc05ab567e1b92902bde`

Generic inference retained the opaque task scope but discarded the physical
data root before invoking the task-owned writer. The writer therefore could
not rematerialize the same validation samples through the public contract and
failed with:

~~~text
RuntimeError: generic inference did not carry the run-bound deliverable source context
~~~

## Repair acceptance

SIDERIUS repair revision: `26c1cbd8`.

`DeliverableWriteRequest` now carries an optional typed
`DeliverableSourceContext`: the physical data root, the number of produced
samples, and the fixed `validation_dataset` index-order contract. A task that
needs auxiliary values can rematerialize its own dataset and refuse a count
mismatch. Prediction-only tasks ignore the additive field. No fifth data-path
method and no task-specific framework branch were added.

~~~bash
PYTHONPATH=/path/to/SIDERIUS .venv/bin/python \
  provenance/reproductions/issue_385_deliverable_source_context.py
~~~

Expected terminal output:

~~~text
PASS: deliverable writing recovered prediction-aligned task values
~~~

The witness fails against SIDERIUS `98610b8d` and passes against `26c1cbd8`.
The focused framework compatibility set passes 76 tests, including existing
prediction-only quickstart and declared-naming paths. Ruff and
`git diff --check` pass.
