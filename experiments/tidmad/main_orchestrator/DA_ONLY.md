# Data-analysis-only orchestration deployment contract

Condition: `O-DAOnly`. Add the dedicated Data Analysis capability to the archived
O-NoPrior orchestration control. Model research advice and controller strategy
advice remain absent. Record infra/exp version differences separately; this is
not a claim of identical historical runtime code.

## Prepare and expose only the selected treatment

Use `prepare --data-analysis-only`, mutually exclusive with `--prior` and
`--strategy-only`. It resolves the existing DA-only information declaration,
binds the same frozen band-specific input-only analysis policy used by the
DA-only workflow, and preserves NoPrior execution limits and native role models.
It never reads or copies model advice or controller strategy artifacts.

Retain the existing compact public training composition and private trained-model
loss interface. Add a separate `public_analysis_composition` and an input-only
physical validation view produced by `analysis_input_view.py`. Bind the original
task-path identity and the prepared analysis policy to this analysis composition.
The compact training adapter does not support the analysis capability.
Private validation targets and evaluator source remain inaccessible.

The protected additive `SIDERIUS-RUN.md` must identify O-DAOnly, the analysis
composition, input-only data root, policy digest and toolbox analysis guide.
It must state that model advice and workflow-strategy advice are absent. Use
the existing generic toolkit startup and context-recovery pointers. The coding
agent decides whether and when to call analysis and how to use its findings;
there is no prescribed schedule or guaranteed agent compliance.

Publish only the existing public runtime allowlist plus necessary run bindings.
Do not expose the complete exp checkout, operator preparation, archived runs,
previous findings, model advice, controller strategies or strategy prompt
supplements. Do not pass `--prompt-supplement` to the outer supervisor.
Check visibility with the actual research UID, including alternate paths,
readable archives, login/session history and parent-directory traversal.
A prompt saying not to use advice is not evidence that the advice is absent.

## Per-host comparison against the archived control

Record a row for every check, with the reference path, observed value and
PASS/FAIL status. Reference the same-band archived O-NoPrior run, not a running
strategy-only host or a source document alone.

- Compare all frozen public input bytes, including task/treatment/provenance.
- Compare training population, prepared representation, validation subset,
  candidate/final band scopes, and each data-manifest identity.
- Compare execution policy, model routing, Codex CLI/version/flags, continuing
  24-hour allowance, restart and finalization behavior. Different accounts,
  host/run identities and timestamps are operational metadata, not hidden
  scientific treatment differences; record them explicitly.
- Compare the deployed scorer, Health, inference and finalizer code against
  archived control hashes. A version-driven change still needs a reviewed
  diff; it is not an automatic parity waiver.
- Invoke `tidmad-score --help` as the research UID through its actual command
  and sudo route. Check evaluator imports, policy, receipts/candidate roots,
  and evaluator/inference ownership. Verify the inference-session directory
  exists after preparation. Exercise a tiny isolated inference and score
  submission through the installed path, with qualification outputs kept
  separate and removed before the formal clock. Report its limited scope.
- Verify the private loss client and native training/export path remain usable;
  reuse existing bounded smoke fixtures rather than training for quality.
- Verify the actual service invocation has no strategy supplement, and no
  strategy/model-advice artifact is readable under any exposed path.
- Verify backup upload/readback, stop/finalization timers and clean run state.
- For the DA addition, verify input-only HDF5 keys, exact band identity, target
  denial, bwrap/unshare availability and generated-program execution as the
  research UID in the real service environment. A reference-skill-only report
  does not qualify generated-program execution.

Only infra/exp revisions and the declared DA capability/information path may
change experimental conditions. Review any other difference before launch.
Preparation receipts remain `launch_ready: false`; account login or a successful
import alone is not launch qualification. All smoke work is bounded and starts
no formal clock. Record tags, SHAs, host/account mapping, start/deadline and
qualification receipts in the operator inventory before startup closeout.
